# Teddy motion/world engine — runtime slice

## Evidence and scope

This slice starts from `main` after PR #9. Teddy already has a v6 articulated hierarchy and the v7.1 visual refinement layer; the missing capability is runtime composition: the gait exists but does not translate Teddy through a bounded world, semantic LLM output does not trigger body actions, and the visual environment has no explicit scenario layer behind the WebGL floor.

The implementation deliberately leaves the voice/provider control plane untouched. Motion is provider-neutral and consumes the browser-visible semantic/telemetry stream from both local NDJSON turns and OpenAI Realtime events.

## Epistemic slices

1. **M1 — motion contract.** A finite vocabulary (`stand`, walk, turn, arm raise/wave, leg lift, jump, nod), bounded intensity/duration, a queue cap and a bounded stage are represented as pure data.
2. **M2 — articulated runtime engine.** Commands evolve through deterministic phase envelopes; walking drives the inherited hip/knee/ankle and shoulder/elbow gait while the engine also translates the root on the ground plane. Arm/leg actions operate on complete articulated chains.
3. **M3 — physical ground coupling.** Before world translation the runtime derives support-foot contact from the refined foot geometry and ankle matrices, then applies a bounded vertical correction against `FLOOR_Y`. A lifted leg uses the contralateral support foot.
4. **M4 — scenario/background.** The existing WebGL floor remains the physical plane. A separate plush-studio backdrop and horizon sit behind the transparent canvas and receive bounded parallax from world motion.
5. **M5 — LLM/telemetry routing.** Local NDJSON events are mirrored as `teddy:local-event`; Realtime events are intercepted before application handling. Natural-language action semantics and explicit `metadata.motion` telemetry are sanitized into the same motion intents. Unknown actions are ignored.
6. **M6 — composable invariants.** Finite state, bounded stage/yaw/speed/duration/phase/queue, known bounded actions, mutually exclusive ground/air state, floor penetration/slip limits, single-leg support and jump-airborne consistency compose into one falsifiable safety contract.
7. **M7 — saturation and mutation.** Exactly 1,000,000 deterministic movement/articulation scenarios are checked against the invariant set, plus 10,000 real `MotionEngine` sequences / 1,500,000 engine frames. A separate 1,000,000-identity critical mutation campaign attacks 25 invariant surfaces and requires every mutation to be killed.

## Runtime routing

`response transcript / input transcript / explicit telemetry -> motion intent sanitizer -> bounded queue -> MotionEngine -> locomotion + articulated action -> support-foot grounding -> world transform -> motion-frame telemetry -> backdrop parallax`

The response parser recognizes only a small explicit physical-action vocabulary and includes a negation guard. It is not a general natural-language executor and never evaluates model-produced code.

## Saturation semantics

The million scenario identities and million mutation identities are deterministic numerical/state-space exploration, not claims of one million physical browsers or GPU renders. The normal CI continues to execute the inherited renderer/security/runtime tests; the new `motion-v8` workflow separately requires the full scenario and mutation reports to reproduce byte-for-byte.

## Residual falsifiable boundary

This slice materially improves physical grounding by measuring refined support-foot contact, but it is not a full IK solver and does not claim zero sub-pixel foot sliding in every browser camera/render path. A future browser/video golden gate can falsify temporal foot slip and silhouette continuity directly from rendered frames.
